# Flora Garden Test — Compact Edition

รุ่นลดขนาดสำหรับนำเข้าและรันบน Google AI Studio โดยคงการทำงานของหน้าเว็บ,
Firebase, ระบบสำรอง/กู้คืน และเซิร์ฟเวอร์เดิม

## การรัน

```bash
npm install
npm run dev
```

เซิร์ฟเวอร์เริ่มต้นที่ `http://localhost:3000`

## Flora-Test-New-1
- กรุณาช่วยจำไว้ว่า อธิบาย เป็นภาษาไทย ไม่ต้องแสดง Code
- รวมศูนย์ระบบบุคลากรไว้ใน `org_chart.html` เป็น 4 แท็บ: ผังบุคลากร, สารบบบุคลากร, Tree และลงเวลา/การลา
- แท็บ “ผังบุคลากร” คงหน้าตาและการจัดวาง Interactive Org Chart เดิมทุกส่วน
- Tree เป็นแหล่งข้อมูลกลางสำหรับโครงสร้างแผนกและตำแหน่ง
- เพิ่ม แก้ไข และลบโหนดจาก Tree แล้วผังบุคลากรใช้ข้อมูลชุดเดียวกัน
- Popup “กำหนดตำแหน่งลงผังทันที”, แบบฟอร์มบุคลากร, ตัวกรอง และรายการย้ายข้อมูลสร้างตัวเลือกจาก Tree อัตโนมัติ
- Popup กำหนดตำแหน่งใช้การบันทึกแบบครั้งเดียว ป้องกันคำสั่งซ้ำและไม่เขียนข้อมูลย้อนกลับจาก Firestore Snapshot
- Dropdown “กำหนดตำแหน่งลงผังทันที” ใช้หน้าตา กลุ่มระดับ และรายการเดียวกับช่อง “ตำแหน่งงานในโครงสร้าง”
- บุคลากรเชื่อมกับโครงสร้างด้วย `departmentNodeId` และ `positionNodeId`; เมื่อแก้ชื่อหรือเลขโหนด ระบบปรับข้อความอ้างอิงโดยไม่ทำให้คนหลุดจากตำแหน่ง
- ป้องกันการลบโหนดที่ยังมีโหนดย่อยหรือบุคลากรอยู่
- ถอดปุ่ม “โยกย้ายโครงสร้าง” และ “จัดการตำแหน่ง/แผนก” ที่ซ้ำซ้อนออกจากหน้าปกติ
- รองรับนำเข้า/นำออก JSON และบันทึก Tree ผ่าน Firestore; localStorage ใช้เป็นข้อมูลสำรองเมื่อเชื่อมฐานไม่ได้เท่านั้น
- `index.html` เป็นพื้นที่งานคลังอุปกรณ์ ไม่แสดงหน้าจัดการบุคลากรหรือหน้าลงเวลา
- หน้าคลังอ่าน collection `employees` เพื่อเลือกผู้เบิก/ผู้ยืมเท่านั้น และไม่มีเส้นทางเขียนแก้ข้อมูลบุคลากร
- การเพิ่ม แก้ไข ลบ หรือย้ายบุคลากรทำที่ `org_chart.html` เท่านั้น ส่วนการแก้โครงสร้างทำที่แท็บ Tree เท่านั้น
- เมื่อ Firestore เชื่อมต่อสำเร็จ รายชื่อจากฐานหลักเป็นข้อมูลจริงเพียงชุดเดียว และจะไม่ผสมรายชื่อเก่าจาก localStorage กลับเข้ามา
- การลงเวลา/การลาถูกย้ายมาอยู่ใน `org_chart.html` และเขียน collection `attendance` ในฐานหลักเดียวกัน
- สารบบรองรับตาราง/การ์ด ค้นหา กรอง เรียง เลือกหลายคน พิมพ์บัตรรายคน/หลายคน/ทั้งหมด พร้อม QR และปรับรูปแบบกระดาษ
- รองรับประวัติเบิก–จ่าย–ยืม–คืนรายบุคคล, สแกน QR บุคลากร, นำเข้า Excel, ดาวน์โหลดไฟล์ตัวอย่าง และส่งออก CSV
- รูปบุคลากรใหม่บีบอัดอัตโนมัติแล้วอัปโหลด Firebase Storage; Firestore เก็บเฉพาะ URL พร้อมกล้องมือถือและกล้องสด
- การบีบอัด/ย้ายรูปเดิมเป็นคำสั่ง Admin แบบกดสั่งเท่านั้น และทุกการแก้บุคลากรถูกบันทึกใน `audit_logs`
- `org_chart.html` ตรวจสิทธิ์ Admin โดยตรงจาก Firebase Auth/เอกสารผู้ใช้ และรับช่วง Quick Login Admin เฉพาะ session เดียวกัน; ผู้ใช้อื่นเปิดดูได้อย่างเดียว
- ไฟล์หน้าสารบบ `personnel_tools.js` โหลดเป็น Vite module เพื่อให้ถูกบรรจุใน `dist` ทั้งโหมดพัฒนาและโหมดเผยแพร่ พร้อมหน้าสถานะสำรองหากโหลดไม่สำเร็จ
- การลบบุคลากรเป็น Soft Delete: สำรองข้อมูลเต็มไป `deleted_employees` ก่อนลบจาก `employees` พร้อมผู้ลบ วันเวลา เหตุผล และตำแหน่งเดิม
- Admin เปิด “บุคลากรที่ลบแล้ว” เพื่อกู้คืนด้วยรหัสเดิมได้; ถ้าโหนด Tree เดิมหายจะคืนไป “รอลงผัง” และไม่เขียนทับรหัสที่มีอยู่
- การลบถาวรต้องยืนยันสองครั้ง ส่วนไฟล์สำรอง JSON/ZIP รุ่นใหม่รวม `deletedEmployees` และกู้คืนกลับฐานหลักได้
- การซิงค์จาก V.2 และการสำรอง/กู้คืนยังเป็นคำสั่งผู้ดูแลที่ทำงานต่อเมื่อ Admin กดสั่งเท่านั้น
- ระบบทำงานประจำวันชี้ฐานหลัก `ai-studio-floragardentest-b067b23c-205a-446d-8774-e8804286e5e1` เพียงฐานเดียว; Database ID อื่นจะถูกเปิดอ่านได้เฉพาะตอน Admin สั่งซิงค์ด้วยตนเอง
- ตำแหน่งผู้บริหารใช้ `positionNodeId` โดยตรง จึงไม่ดึงบุคลากร `ADMIN` ทุกคนไปแสดงซ้ำเป็นประธานโครงการ
- จำกัดผู้ดำรงตำแหน่งประธาน 1 คน, ที่ปรึกษา 2 คน และผู้ประสานงาน 1 คน; หากเต็มต้องย้ายบุคลากรเดิมออกก่อน

## สิ่งที่ลดออก

- ไฟล์ `navbar.html` และ `modals.html` ซึ่งเป็นสำเนาที่ไม่ได้ถูกอ้างอิงตอนรันจริง
- `sw.js` ที่ root ซึ่งซ้ำกับไฟล์ใช้งานจริง `public/sw.js`
- เอกสารบันทึกการพัฒนาและ lock file ว่างที่ไม่เกี่ยวกับ runtime
- dependencies ของ React, Tailwind, Gemini SDK, Firebase npm และไลบรารีอื่นที่ไม่มี import ใน runtime
- Vite middleware สำรองที่ไม่มีผู้เรียกใช้ โดย API ที่หน้าเว็บเรียกจริงยังอยู่ครบใน `server.ts`

## ส่วน Login ที่ล็อกไว้

การปรับครั้งนี้ไม่เปลี่ยนหน้าตา Login หรือขั้นตอน Google/Email Login เดิม แต่เพิ่ม
การส่งต่อสิทธิ์ Quick Login ภายใน `sessionStorage` เพื่อให้ `org_chart.html`
ตรวจ Admin ได้โดยตรง ส่วน
`firebase-applet-config.json` ยังคงใช้ฐานหลักเดิมเพียงฐานเดียว

## หมายเหตุ

Firebase SDK ฝั่งหน้าเว็บโหลดจาก CDN โดยตรง จึงไม่ต้องติดตั้งแพ็กเกจ `firebase`
จาก npm ส่วน Bootstrap และไลบรารีหน้าเว็บอื่นยังโหลดจาก CDN ตามต้นฉบับ
